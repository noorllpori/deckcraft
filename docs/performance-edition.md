# DeckCraft 性能版：功能与性能说明

更新日期：2026-10-18。适用版本：0.6.2-performance.1。主要面向大图、多页演示文稿的 Windows 桌面编辑和放映。

本分支由葡萄拌大蒜（[@noorllpori](https://github.com/noorllpori)，[B 站](https://space.bilibili.com/38222138)）独立维护。基础项目与上游贡献者仍归属 Storytold DeckCraft，性能版不代表官方版本。

## 目前能做到什么

### 编辑与导航

- 顶部“高性能”开关可开启编辑预览优化，设置会保存。
- 主要画布针对当前页渲染，切页后释放上一页的主画布缓存；文档、原始媒体、撤销历史等仍保留，**不是把其他页面的数据全部从内存卸载**。
- 原生桌面端通过后台工作线程渲染；拖动时使用整页低分辨率代理，图片、文字仍按原图层顺序遮挡。
- 同页编辑等待新画面时保留之前可显示的帧；这是减少闪烁的处理，不保证所有机器或内容完全无闪烁。
- 放大后中键平移，滑块、快捷键等缩放围绕编辑区中心；“适应窗口”恢复居中，平移受画布滚动边界约束。
- Multi-Function 上方选择列表独立滚动，下方显示选中元素属性；图片显示文件名、来源及外链路径。

### PSD 与链接图片

- “插入图片”及拖入本地 PSD 默认保存外部链接；常规 PNG/JPEG 等仍默认内嵌。没有本地路径的字节导入无法建立持久外链。
- 支持 RGB／灰度 8／16 位 PSD 的已保存合成画面，支持 Raw、RLE、ZIP 和 ZIP 预测压缩；不拆解图层。
- 选中或重复点击图片、选择列表条目时，在后台读取文件并计算 SHA-256；只有内容改变且可解码时更新。哈希记录到原生 `.deckcraft` 文件。
- 哈希不变时不重新解码、不清理画布缓存、不增加撤销记录；但检查仍要读取和计算源文件，巨大文件或慢速网络盘仍有 I/O 成本。
- 可手动刷新、将外链源文件打包进演示文稿、将内嵌图片解包为外部文件。PSD 操作保留原始字节。
- 不是磁盘持续监听；链接依赖原路径，移动／删除源文件后需恢复路径。尚无重新定位向导。

### 放映准备与文件操作

- 独立预编译操作只准备缓存，不直接开始放映；状态面板列出页面是否就绪、过期或失败。
- 开启自动编译后，切页会安排刚离开的页面及当前页；空闲约 1.5 秒后排队处理其余页面。修改后相关缓存需重新生成，媒体变化可能使多页缓存失效。
- 开始放映也会后台启动准备。缓存未就绪时有实时渲染回退，因此首次播放、复杂效果或失败页面仍可能卡顿。
- 保存和读取有进度界面，并将文件工作移出界面线程；不等同于全部 PPT 页面并行加载。
- 简体中文界面、性能版独立名称与署名已接入。现有配置沿用，当前官方版与性能版仍可能共用 DeckCraft 配置目录。

## 性能具体改善在哪里

以下来自代码中的策略与上限，属于实现参数，**不是跑分结果，也不是总进程内存或帧率保证**。

| 环节 | 当前策略／参数 | 减少的工作与代价 |
|---|---|---|
| 高性能编辑预览 | 名义画布像素预算约 180 万，最长边 2048 px | 避免随高倍缩放生成过大主画布；高倍显示可能偏软，画布外区域还可能扩展实际纹理 |
| 拖动代理 | 名义预算约 36 万像素，最长边 960 px | 拖动期间减少整页像素处理；松手再准备常规预览，移动时细节降低 |
| 缩略图 | 缓存条目上限从普通模式的 600 调整为高性能模式的 24 | 降低缩略图纹理保留量；回看旧页可能重新生成。不是总显存减少到 1/25 |
| 桌面后台渲染 | 当前页工作移到线程，等待时显示可用旧帧 | 减少重渲染直接阻塞交互；不能消除 CPU 竞争、纹理上传和所有界面开销 |
| 放映预编译 | 动画按 30 帧/秒准备；按屏幕与幻灯片比例取尺寸，最长边 2560 px、约 369 万像素预算 | 将部分实时渲染提前完成；需要等待准备，画面可能低于高分屏原生分辨率，不保证实际播放恒定 30 fps |
| 放映内存缓存 | 64×64 像素块复用，缓存预算 2048 MiB，最多 18000 帧 | 相同区域减少重复存储；帧重建、上传、模型及其他缓存仍有额外内存开销，预算不是预先分配 2 GiB |
| 链接刷新 | 一个后台工作任务，内容哈希变化才替换 | 避免每次点击都解码、使缓存失效；仍需读取文件，无变化不是零开销 |

例如，拖动预算 36 万是常规高性能预览预算 180 万的五分之一，这是**预算之间的关系**，不能换算为速度提升五倍。CPU、字体、效果、媒体数量、磁盘与显卡上传都会影响实际表现。

实现位置：[textures.rs](../crates/ui-egui/src/textures.rs)、[playback.rs](../crates/ui-egui/src/playback.rs)、[show.rs](../crates/ui-egui/src/show.rs)、[linked_pictures.rs](../crates/ui-egui/src/linked_pictures.rs)。

## 暂不承诺的能力与已知限制

- 未替换成全 GPU 渲染引擎；主要幻灯片渲染仍使用现有 CPU 渲染路径。高性能模式不是硬件性能倍增器。
- 并非所有放映内容都走预编译缓存：视频、动态 GIF 等内容有实时路径；复杂动画、转场及兼容性仍需实际文件验证。
- 不支持 PSD 图层编辑、CMYK、Lab、索引色、32 位、PSB 或 ICC 色彩转换。解码有尺寸与内存限制，详细见 [PSD 文档](psd-linked-pictures.md)。
- PPTX 保留 PSD／外链不代表其他软件能显示；尚无 PNG 兼容回退。对外交付建议使用 PNG，或先确认接收端支持。
- 原始源图不会因编辑代理而被缩小覆盖，但放映缓存有单独尺寸限制；编辑预览优化也不代表导出被加速。
- Windows Debug 构建、改动文件格式及差异检查已完成；按贡献者要求，实际界面与文件验证由贡献者进行。未完成全量回归、跨平台验证或可复现的性能基准测试。

## 后续怎样量化提升

发布跑分前，应固定电脑、文件、窗口尺寸、显示缩放和版本，分别测普通模式与高性能模式；冷缓存和热缓存分开记录。建议记录打开／保存时间、拖动帧耗时、输入响应时间、进程峰值内存、预编译时间和放映延迟，至少重复三次并公布中位数。

在这些数据完成前，本项目只说明已实现的优化方式、适用场景和代价。
